# Central Business Hub

بوابة أعمال B2B عربية متعددة الشركات، مبنية على React وTypeScript وNode.js وPostgreSQL. تدير التطبيقات بيانات فعلية محفوظة في قاعدة البيانات؛ لا توجد بيانات أعمال محلية للعرض.

## الوظائف الحالية

- تسجيل المستخدمين والشركات، الجلسات الآمنة، العضويات والأدوار، ومراجعة اعتماد الشركات من حساب مشغل المنصة.
- بوابة عامة منفصلة للشركات، وسوق عام للمنتجات، ودليل عام للخدمات؛ تعرض البوابات العامة السجلات النشطة المعتمدة فقط، بينما تبقى عمليات الطلب داخل حساب شركة مشترية.
- ملفات الشركات والفروع، كتالوج المنتجات والخدمات، طلبات الخدمات المرتبطة بالخدمة ومقدمها.
- كتالوج توريد يتضمن التسعير المعلن أو طلب التسعير، وشرائح الكميات، وسعة الإنتاج، ومدة التجهيز، ومناطق التوزيع ومواصفات المنتج.
- طلبات عروض الأسعار متعددة الموردين، مع إسناد بنود المنتجات إلى المورد المالك، وقبول عروض جزئي أو كامل، وإنشاء أمر شراء مستقل لكل مورد مقبول.
- الشحن وإسناد الناقلين والمركبات والسائقين وتحديث الحالة وإثبات التسليم.
- المستودعات والأرصدة وحركات المخزون والتحويلات والجرد والتنبيهات.
- العقود وموافقات الأطراف والفواتير وتسجيل الدفعات الخارجية والاشتراكات.
- المطالبات، مؤشرات الأداء، سجل التدقيق، وإعدادات التكامل.

## المتطلبات

- Node.js 22.12 أو أحدث وnpm 10.9 أو أحدث.
- PostgreSQL 15 أو أحدث. أنشئ قاعدة بيانات فارغة باسم `central_hub` أو استخدم قاعدة مخصصة.

لا يتضمن المشروع Docker أو إعدادات حاويات.

## إعداد قاعدة البيانات

من جذر المشروع، أنشئ ملف الإعداد المحلي من المثال ثم حدّث بيانات اتصال قاعدة البيانات:

```powershell
Copy-Item apps/api/.env.example apps/api/.env
```

اضبط `DATABASE_URL`، وفعّل `DATABASE_SSL=true` عند استخدام اتصال PostgreSQL يتطلب TLS. لا تضع ملف `.env` أو بيانات اعتماد حقيقية في المستودع.

ثبّت الاعتماديات، ثم أنشئ المخطط وحساب مشغل المنصة:

```powershell
npm install
npm run db:migrate
npm run db:seed-admin
```

قبل تشغيل `db:seed-admin`، اضبط `ADMIN_EMAIL` و`ADMIN_PASSWORD` و`ADMIN_NAME` و`ADMIN_COMPANY_NAME` في `apps/api/.env`. يجب أن تتكون كلمة المرور من 12 محرفًا على الأقل، وأن تحتوي أحرفًا كبيرة وصغيرة ورقمًا ورمزًا. يرفض الأمر استبدال مستخدم موجود. احذف قيمة كلمة المرور من البيئة بعد إنشاء الحساب، وغيّرها وفق سياسة المؤسسة.

## التشغيل

شغّل كل أمر في نافذة طرفية مستقلة من جذر المشروع:

```powershell
npm run dev:api
```

```powershell
npm run dev:web
```

واجهة الويب: `http://127.0.0.1:5173`

فحص API وقاعدة البيانات: `http://127.0.0.1:4000/api/health`

## بوابات الويب

- `/` الموقع التعريفي واختيار مساحة العمل.
- `/companies` تسجيل الدخول ومساحة العميل أو الشريك أو مشغل المنصة.
- `/supply` سوق التوريد العام؛ اختيار المنتجات وإرسال طلب عروض الأسعار يتطلب حساب شركة مشترية، ويُسجل الطلب في مساحة الشركة.
- `/services` دليل الخدمات العام؛ طلب الخدمة يرتبط بسجل الخدمة ومقدمها ويتطلب حساب شركة مشترية.

تُخدم هذه المسارات من تطبيق الويب نفسه لتسهيل التطوير المحلي؛ فصل التجارب والصلاحيات لا يعني أنها منشورة على نطاقات مستقلة. النطاقات الفرعية وتسجيل الدخول الموحد بينها تتطلب إعداد نشر وملفات ارتباط ونطاقات CORS مناسبة قبل الإطلاق.

## النشر على Render باستخدام مستودع GitHub خاص

يستضيف Render الواجهة وواجهة API من الخدمة نفسها، مع PostgreSQL متصل داخليًا. هذا يحافظ على جلسات الدخول وطلبات API على النطاق نفسه؛ GitHub Pages وحده لا يشغّل Node.js أو PostgreSQL. إعداد `render.yaml` الحالي يستخدم خطط Render المجانية لتجربة مؤقتة من دون وسيلة دفع.

**حدود مهمة للخطة المجانية:** خدمة الويب تدخل السبات بعد 15 دقيقة من عدم وصول طلبات، وملفاتها المحلية مؤقتة وتُفقد عند إعادة التشغيل. قاعدة Render المجانية محدودة بـ1 GB وتنتهي بعد 30 يومًا؛ لا يمكن الوصول إليها بعد الانتهاء، وتحذف Render قاعدة البيانات وبياناتها بعد مهلة سماح 14 يومًا إن لم تتم الترقية. لا تدعم هذه القاعدة النسخ الاحتياطية. لا تخزن بيانات حقيقية أو حساسة في هذه التجربة، وصَدّر أي بيانات تريد الاحتفاظ بها قبل انتهاء المدة.

تُنشئ الخدمة في كل بدء مجموعة كتالوج للعرض تضم موردين وستة منتجات خيالية بصور توضيحية. تظهر عليها علامة واضحة بأنها تجريبية، وجميع الأسعار والسعات والمواصفات غير حقيقية. يتحكم المتغير `DEMO_DATA_ENABLED=true` في Render بإنشاء هذه المجموعة؛ عطّله قبل استخدام قاعدة البيانات لأي بيانات فعلية.

صور المنتجات التوضيحية محفوظة محليًا داخل `apps/web/public/demo-products`، ومصدرها [Unsplash](https://unsplash.com/license). لا تمثل الصور منتجات الموردين أو بضائع متاحة للبيع.

1. مصدر المشروع موجود في المستودع الخاص [central-business-hub](https://github.com/nasserbwwg-ship-it/central-business-hub) على الفرع `main`، وملف `apps/api/.env` وبيانات الاعتماد المحلية مستثناة من Git.
2. في Render، أنشئ Blueprint من المستودع والفرع `main` باستخدام `render.yaml`، واختر الخطط المجانية للخدمة وقاعدة البيانات إن ظهرت شاشة اختيار الخطط.
3. انتظر اكتمال نشر الخدمة وترحيلات قاعدة البيانات. النسخة المنشورة حاليًا: [central-business-hub.onrender.com](https://central-business-hub.onrender.com). صحة الخدمة وقاعدة البيانات: [`/api/health`](https://central-business-hub.onrender.com/api/health).
4. **لم يُنشأ حساب مشغل أو حساب تجريبي.** خدمة Render Free لا توفر Shell، ولذلك لا يمكن تشغيل `npm run db:seed-admin --workspace @central-hub/api` من لوحة الخدمة. لا تفتح تسجيل المستخدمين لاستخدام فعلي يتطلب اعتماد الشركات قبل إعداد مشغل بطريقة آمنة.

تُخدم الواجهة وواجهة API من النطاق نفسه؛ تتضمن مسارات الواجهة `/`, `/companies`, `/supply`, و`/services`. للتحقق اليدوي من التشغيل افتح الرابط بعد الاستيقاظ من السبات وانتظر استجابة التطبيق.

كل دفع جديد إلى `main` يعيد بناء الخدمة ويطبّق الترحيلات المرقمة قبل بدء API. هذه الإعدادات مخصصة للتجربة المجانية المؤقتة فقط وليست مناسبة للإنتاج. لا تشارك رموز الوصول أو كلمات المرور في المحادثة.

## ملاحظات تشغيلية

- التسجيل العام ينشئ شركة بانتظار اعتماد المشغل. لا تمنح أي مستخدم عام صلاحية مشغل المنصة.
- نفّذ الترحيلات على نسخة احتياطية في البيئات القائمة. لا تعدّل ترحيلًا سبق تطبيقه يدويًا؛ أضف ترحيلًا جديدًا متوافقًا مع مخطط قاعدة البيانات الفعلي.
- صلاحيات الوصول وعزل البيانات يطبّقان في API، لكن إعداد TLS، النسخ الاحتياطي، المراقبة، تدوير الأسرار، وإدارة دورة حياة الحسابات مسؤوليات تشغيلية يجب تهيئتها قبل الإنتاج.
- تسجيل الدفعات يوثق مرجع دفع خارجيًا فقط؛ لا ينفذ تحويلًا ماليًا. إعدادات التكامل لا تنشئ اتصالًا فعليًا مع ERP أو POS. موافقات العقود تسجل موافقة داخل المنصة ولا تمثل توقيعًا إلكترونيًا معتمدًا.
- لا يتضمن الكتالوج حاليًا تخزين صور المنتجات أو التحقق الآلي من تراخيص مقدمي الخدمات. التكاملات والذكاء الاصطناعي وتطبيقات الأجهزة وتتبع GPS ليست خدمات تشغيلية مفعلة بمجرد ظهورها ضمن تصور المنظومة.
- تعذر إكمال اختبار قاعدة البيانات أو تدفق طلب حقيقي ما لم تُهيأ PostgreSQL وملف `apps/api/.env` ببيانات اتصال صالحة.
- لا تستخدم المنظومة في الإنتاج قبل مراجعة أمنية مستقلة، اختبار الاستعادة، إعداد HTTPS، وتحديد سياسات الاحتفاظ بالبيانات والصلاحيات.
